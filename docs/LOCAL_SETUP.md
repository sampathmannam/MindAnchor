# Building and running MindAnchor on your own machine

Everything in this repo was written and tested through CI, without a
local Android SDK. This is the other way in: clone, build, and run it on
an emulator or on your phone.

## What you need

- **Android Studio** (Ladybug or newer). Its bundled JDK 17+ is enough —
  there is nothing to install separately.
- In **Settings → Languages & Frameworks → Android SDK → SDK Tools**,
  tick **NDK (Side by side)** and **CMake**. The app pins
  `ndkVersion = "27.3.13750724"`; if the SDK Manager offers a different
  NDK, install that one and change the single `ndkVersion` line in
  `app/build.gradle.kts` to match.
- ~15 GB free: the SDK, the NDK, and the native build of the vendored
  `llama.cpp` are not small.

## Clone and build

```
git clone https://github.com/sampathmannam/MindAnchor
cd MindAnchor
./gradlew assembleDebug
```

The first build compiles `llama.cpp` for two ABIs and takes several
minutes. Later builds reuse it and are quick.

## An emulator that can actually run this app

Create an AVD with **API 33 or higher** (`minSdk = 33`) on the
**x86_64** image — the app packages `arm64-v8a` and `x86_64` precisely so
the engine loads on a desktop emulator. Give it 4 GB of RAM.

```
./gradlew installDebug        # install on the running emulator
./gradlew test                # unit tests, no device needed
./gradlew connectedAndroidTest  # instrumented: screenshots, semantics, engine
```

`connectedAndroidTest` is where the interesting checks live: the
accessibility walk of every surface, the WCAG contrast test, and
`EngineTest`, which proves the native library loads and its backend
comes up.

### Making it the launcher

The emulator's home button will offer MindAnchor once it is installed;
pick it and choose "Always". To get back to the stock launcher, use
**Settings → Apps → Default apps → Home app**.

## What an emulator cannot show you

Three things need real hardware, and no AVD substitutes for them:

- **Camera PPG.** The emulator's fake camera produces no pulse. HRV
  measurement only works with a fingertip on a real lens and flash.
- **Health Connect.** Not present on emulator images. Wearable-sourced
  signals stay empty; the coverage screen will say so honestly, which is
  itself worth seeing.
- **The screen-rhythm signals.** First pickup and screen time come from
  a real usage-event history. An AVD you booted an hour ago has one.

## Running the model

Settings → Reading → Model → *Add a model from a file*, and pick a GGUF.
A 4-bit ~3B instruct model (roughly 2 GB) is the right size: the screen
states plainly whether this device can run what you gave it. Then
Settings → Reading → *Build last night's look now* to run the whole
nightly pipeline in the foreground instead of waiting for 3am.

On an emulator, generation is slow — minutes, not seconds. That is the
emulator's CPU, not the engine.

## Release builds and the signing key

`./gradlew assembleRelease` falls back to the debug key unless four
environment variables are set: `MINDANCHOR_KEYSTORE`,
`MINDANCHOR_KEYSTORE_PASSWORD`, `MINDANCHOR_KEY_ALIAS`,
`MINDANCHOR_KEY_PASSWORD`. See `docs/RELEASING.md` for the `keytool`
command that generates the key and the CI secrets it maps to.
It must be generated by you and never committed; `.gitignore` refuses
`*.jks` so an accidental `git add` cannot leak it.
