**Goal:** Build the missing letter inbox + reader surface (closing the v0.24.0 letter UI gap) and add a 3-size reader-mode toggle (WCAG 2.2 SC 1.4.4) on top.

**Architecture:** Two atomic releases that ship as v0.25.2:

- **v0.25.2-B (Tasks 13–23)**: new `ReaderPrefs` DataStore, `ReadingSize` (SMALL 14sp / MEDIUM 18sp / LARGE 32sp), a `SingleChoiceSegmentedButtonRow` in the reader header and in Settings → Reading, the letter body/title/disclaimer scale with the chosen size, the WCAG 1.4.4 layout-safety finding test pins the worst case (LARGE + 4000-char body).

**Tech Stack:** Kotlin 1.9.x, Jetpack Compose, Material 3 (`SingleChoiceSegmentedButtonRow`, `SegmentedButton`), DataStore, kotlinx.coroutines Flow/StateFlow. No new third-party dependencies.

## Global Constraints

- All Compose `Modifier.padding(end = 8.dp)` on right-edge containers — the v0.25.1 Bug 6 fix. Every new right-edge TextButton/IconButton in this plan uses `.padding(end = 8.dp)` after `statusBarsPadding()`/`navigationBarsPadding()`.
- Detekt `LongMethod` threshold 60 / `LongParameterList` 8 / `CyclomaticComplexMethod` 15. Extract a state class + sub-Composables for any Composable that exceeds.
- Detekt `MagicNumber` `ignoreNumbers`: `['-1', '0', '1', '2', '7', '10', '14', '100']`. Extract named constants for anything else (notably `200` for the WCAG percentage, `18`, `32`).
- Detekt `ReturnCount` max 4. Many existing decode functions in baseline.
- Detekt line length 120 chars max. Split regex patterns at non-trivial boundaries.
- `internal` (not `private`) for testable helpers and constants so JVM unit tests can reach them. `private` for purely internal Composable sub-functions that don't need test access.
- `remember { … }` for `ActivityResultContract` factories and any DataStore instance.
- Forward-only detekt baseline (`config/detekt/baseline.xml`) — never regenerate to silence findings.
- `android.util.Base64.encodeToString` and `android.net.Uri.parse` are stubs on JVM unit tests — use `java.util.Base64` with `.withoutPadding()` for Basic Auth, take `String?` instead of `Uri?` for filter functions.
- `uiautomator dump` is the only reliable way to get exact bounds for `adb input tap` (1080×2400 emulator displays at 900×2000, a 1.20x scale).
- Tap coordinates: use x=1000 for top-right, x=959 for bottom-right, NOT 1070+ (off-screen).
- Bug 4 haptics: `LocalHapticFeedback.current.performHapticFeedback(HapticFeedbackType.LongPress)`, AFTER `onSave(draft)`. 5ms tick. Only on capture surfaces.
- The `*Shimmer*` and `*Finding*` test naming convention from v0.25.0. `*Finding*` tests pin file shape; `*Shimmer*` tests pin classifier shimmer; behavioural tests use plain `*Test*`.
- "Be specific and idempotent" pass criterion language in tests.
- All new Composable functions use `@Suppress("FunctionNaming")` (PascalCase is the Compose convention; project baseline has every existing Composable; suppress rather than add to baseline).
- `kotlinOptions { javaParameters = true }` in `app/build.gradle.kts` (added in Task 2). All finding tests that assert on `Parameter.getName()` rely on this flag — without it, the compiler emits `arg0/arg1/arg2/...` and the tests fail with `expected:<[date]> but was:<[arg2]>`. This is a one-time project-wide change, not per-task.
- The `NetworkCallsForbiddenTest` is the build-time gate; this plan adds no outbound network calls.
- The `SealedCodecs` round-trip is preserved; this plan does not add new persisted fields except for `ReaderPrefs` (a new DataStore, not a new field on an existing codec).

## Task 1: `friendlyLetterDate(date, today)` helper

**Files:**
- Create: `app/src/main/java/org/mindanchor/letters/LetterDateFormat.kt`
- Test: `app/src/test/java/org/mindanchor/letters/LetterDateFormatFindingTest.kt`

**Interfaces:**
- Consumes: `java.time.LocalDate` for `date` and `today`; the system clock is read in the caller, not the helper, so the helper is pure.
- Produces: `internal fun friendlyLetterDate(date: LocalDate, today: LocalDate): String` — returns "Today" / "Yesterday" / weekday name (e.g. "Monday") / `MMM d` for 1–7 days ago… wait, see Step 1; the rule is "1–7 days ago = weekday name, > 7 days = MMM d, < 0 days = the future case".

The pin rules for the test:
- `date == today` → "Today"
- `date == today - 1 day` → "Yesterday"
- `date == today - 3 days` → "Monday" (whatever the weekday is for today - 3)
- `date == today - 14 days` → `MMM d` formatted with `DateTimeFormatter.ofPattern("MMM d", Locale.ENGLISH)` (e.g. "Jul 28" if today is Aug 11)
- `date == today - 14 days AND date.year != today.year` → `MMM d, yyyy` (e.g. "Jul 28, 2025" if today is Aug 11 2026)

package org.mindanchor.letters

import java.time.LocalDate
import java.time.format.DateTimeFormatter
import java.util.Locale

/**
 * The human-friendly date label used by both the inbox row and the
 * group-separator header. Same shape as the existing report's
 * [org.mindanchor.report.ReportScreen.friendlyDay] but exported as
 * `internal` so the inbox and the finding test can share one
 * implementation.
 *
 * Rules (pinned by LetterDateFormatFindingTest):
 *   - same day        -> "Today"
 *   - one day before  -> "Yesterday"
 *   - 2..7 days back  -> weekday name, English (e.g. "Monday")
 *   - 8+ days back, same year -> "MMM d" (e.g. "Jul 28")
 *   - 8+ days back, other year -> "MMM d, yyyy" (e.g. "Jul 28, 2025")
 *
 * `date` is the letter's date; `today` is the caller's idea of
 * "today" (the system clock on the device). The helper does NOT
 * read the clock itself so the test can pin every branch.
 */
internal fun friendlyLetterDate(date: LocalDate, today: LocalDate): String {
    val daysAgo = java.time.temporal.ChronoUnit.DAYS.between(date, today).toInt()
    return when {
        daysAgo == 0 -> "Today"
        daysAgo == 1 -> "Yesterday"
        daysAgo in 2..7 -> date.format(DateTimeFormatter.ofPattern("EEEE", Locale.ENGLISH))
        date.year == today.year -> date.format(DateTimeFormatter.ofPattern("MMM d", Locale.ENGLISH))
        else -> date.format(DateTimeFormatter.ofPattern("MMM d, yyyy", Locale.ENGLISH))
    }
}
```

package org.mindanchor.letters

import androidx.compose.runtime.Composable
import java.time.LocalDate
import org.mindanchor.reader.ReadingSize
import org.mindanchor.reader.ReaderPrefs

/**
 * The letter surface, dispatched between an inbox list and a single
 * reader. `selectedDate == null` shows the inbox; a non-null date
 * shows the reader for that date.
 *
 * v0.25.2-A: the inbox and reader Composables are filled in by
 * Tasks 3 and 4. v0.25.2-B: `size` and `onSetSize` are wired in
 * Task 15.
 *
 * `modelFits` controls the empty-state copy and the Generate-now
 * enablement, both inside the inbox; the reader doesn't need it.
 */
@Composable
fun LetterScreen(
    letters: List<Letter>,
    selectedDate: LocalDate?,
    modelFits: Boolean,
    size: ReadingSize = ReadingSize.MEDIUM,
    onSelect: (LocalDate) -> Unit = {},
    onBack: () -> Unit = {},
    onDelete: (LocalDate) -> Unit = {},
    onSetSize: (ReadingSize) -> Unit = {},
) {
    if (selectedDate != null) {
        LetterReader(
            letter = letters.firstOrNull { it.date == selectedDate },
            size = size,
            onBack = onBack,
            onDelete = { onDelete(selectedDate) },
            onSetSize = onSetSize,
        )
    } else {
        LetterInbox(
            letters = letters,
            modelFits = modelFits,
            size = size,
            onSelect = onSelect,
            onDelete = onDelete,
            onBack = onBack,
        )
    }
}

package org.mindanchor.reader

import android.content.Context
import androidx.datastore.preferences.core.edit
import androidx.datastore.preferences.core.intPreferencesKey
import androidx.datastore.preferences.preferencesDataStore
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.map

/**
 * The text size used by every long-form reading surface. v0.25.2-B
 * ships this for the letter; the report will reuse the same
 * `ReaderPrefs` in v0.25.3.
 *
 * Three sizes, pinned by ReadingSizeDefaultsFindingTest:
 *   SMALL  = 14sp  (88% of 16sp baseline)
 *   MEDIUM = 18sp  (default; 113% of 16sp baseline)
 *   LARGE  = 32sp  (exactly 200% of 16sp baseline; the WCAG 2.2 SC
 *                    1.4.4 maximum compliant size)
 */
data class ReadingSize(val sp: Int) {
    companion object {
        val SMALL  = ReadingSize(14)
        val MEDIUM = ReadingSize(18)
        val LARGE  = ReadingSize(32)
    }
}

/**
 * Persists the user's chosen [ReadingSize] across app restarts.
 * Distinct from [org.mindanchor.letters.LetterStore] so a fresh
 * install (no letters yet) still has a size set, and so future
 * reading surfaces (the report, planned for v0.25.3) can share
 * the same DataStore.
 */
class ReaderPrefs(private val context: Context) {

    private val sizeKey = intPreferencesKey("reading_size_sp")

    val size: Flow<ReadingSize> = context.readerDataStore.data
        .map { prefs -> prefs[sizeKey]?.let(::ReadingSize) ?: ReadingSize.MEDIUM }

    suspend fun setSize(size: ReadingSize) {
        context.readerDataStore.edit { it[sizeKey] = size.sp }
    }

    private companion object {
        private val Context.readerDataStore by preferencesDataStore(name = "reader_prefs")
    }
}
```
