# v0.25.8 — SOTA bug-hunt campaign

**Date**: 2026-08-13
**Status**: approved
**Scope**: 1 WP with 7 commits, all from a fan-out-of-6-agents bug hunt on the v0.25.7 install

This is the bug-hunt follow-up. v0.25.6 and v0.25.7 shipped the `BackupRetryWorker` and the on-write trigger wire-up; v0.25.7 also bumped `versionName` from "0.23.0" to "0.25.7". A SOTA bug-hunt campaign against v0.25.7 (6 agents in parallel) found 50+ bugs across the home, settings, notes, letters, vitals, PPG, sleep, report, friction, and backup modules. v0.25.8 picks up the highest-severity findings: 4 P0/HIGH fixes (silent backfill, letter-diff body, home-card classification, id-counter duplication) and 2 P3/MEDIUM polish fixes (long notes, OpenLoop render glitch).

## The 6 fixes in v0.25.8

(Backup #3 stale-snapshot worker, #4 OkHttpClient leak, #5 enqueue/schedule atomicity, #7 silent collector death — all fixed in v0.25.7+WP-2 alongside #1 and #2. Backup #6 GCM AAD, #8 URLEncoder, #9 PendingBackup === are deferred.)

### Bug #1 — Silent backfill on subscribe (HIGH)

`BackupScheduler.start`'s `.scan(NotesDiffState())` seeds the accumulator with an empty previous state. The first DataStore emission's `newOnes` is the entire current list, and the on-write trigger appends every existing note to Drive — silently, the moment the user flips the auto-sync toggle. This contradicts the "Back up now = backfill, on-write = new-only" design.

**Fix**: `.drop(1)` after each `.scan(...)`. The first emission is the seed; the new-write path picks up from there. Same for letters.

### Bug #2 — Letter diff missed body changes (HIGH)

`newLetters` keyed by `date` only. `LetterStore.save` replaces the existing letter for the same date; a re-save produces a list with the new body but the same date. The date-only diff saw the date in `previousDates` and dropped the replacement. New body never reached Drive.

**Fix**: `previous.associateBy { it.date }` + body comparison. The new contract: "any letter that changed (new date, or same date with a new body) is a new write."

### Bug #3 — Home-card `addQuickNote` never enqueued classification (HIGH)

`LauncherViewModel.addQuickNote` saved with `type=null` and never called `ClassifierEnqueuer.enqueue`. The home-card note stayed un-typed even after the classifier ran. The full activity's `onAdd` did enqueue; the home card didn't. v0.25.0's chip promise was broken on the most common path.

**Fix**: `addQuickNote` now calls `ClassifierEnqueuer(getApplication()).enqueue(note)` after `notesPrefs.add(note)`. The classifier is fail-soft (returns GENERAL on error); a future Phi-4 unavailable state degrades to the default, not an untyped note.

### Bug #4 — `idCounter` duplicated (HIGH)

`LauncherViewModel` and `NoteActivity` each had their own `private val idCounter: AtomicLong by lazy {...}`. Two views, two counters, two seeds. A note written from the home card and a note written in the full activity could share an id (both seeded from the same `max(existing, currentTimeMillis)` on first use). Duplicate ids broke every lookup by id: `groupedByDay`, `setType`, `delete`.

**Fix**: `NotesPrefs.nextNoteId()` is a process-singleton id generator (lazy-initialised `AtomicLong` seeded on first use from the max existing id). Both `LauncherViewModel` and `NoteActivity` call it; their private `idCounter` fields are gone.

### Bug #5 — Long single-line notes blew up row height (MEDIUM)

A pasted URL or a long sentence would push the row to fill the screen, pushing other rows off-screen.

**Fix**: `maxLines = 2, overflow = TextOverflow.Ellipsis` on the note row's body Text. The full body is in the activity; the row shows the title (first line) plus a hint of the second.

### Bug #6 — `CorosSyncWorker` activity range hard-coded to 2026 (MEDIUM)

`api.fetchActivities(authed, "20260101", "20261231")` was a build-time constant. The COROS API filters server-side by the from/to range; the constant stopped the activity feed on 2027-01-01.

**Fix**: rolling 12-month window from today. The first sync after New Year still has a full year to draw on; the file size stays bounded.

## Bug-hunt methodology

The 6 agents ran in parallel against `emulator-5554` (API 34, Android 14, sdk_gphone64_x86_64). Each agent had a defined surface (home / settings / notes+letters / backup / vitals+PPG+sleep+report+friction / onboarding+notifications+accessibility) and produced a structured report at `C:\Users\Sampath\github\MindAnchor\.git\sdd\bug_hunt_*.md` with:

- Per-bug: title, severity (P0/P1/P2/P3), exact reproduction, root cause with `file:line`, suggested fix
- Test coverage: what was tested, what wasn't
- Logs: relevant logcat snippets

The agents added 9 new finding tests to the codebase (`OnWriteTriggerFirstEmissionFindingTest`, `WorkerResourceLeakFindingTest`, etc.) that initially asserted the bugs were present. After the v0.25.8 fixes, those tests were rewritten to assert the fixed state. v0.25.8 also adds 2 new finding tests (`HomeCardNotesAndIdUnificationFindingTest`, `QuickNotesCardAboveFoldFindingTest`) for the home-card + layout fixes.

## What was deferred (still in the bug-hunt backlog)

- **Backup #6 GCM no AAD** — entries not bound to file/type. A motivated attacker with Drive write access could swap a Note line into the Letters file. Real but theoretical. v0.25.9+ follow-up.
- **Backup #8 URLEncoder.encode** — Drive `find` query uses form-style `+` (works on current filenames without spaces). v0.25.9+ follow-up.
- **Backup #9 PendingBackup.equals uses === on type** — defensive; only matters for non-singleton ContentType, and v0.25.x only has singletons. v0.25.9+ follow-up.
- **Settings, Onboarding, Notifications, Accessibility** — the bug-hunt agents found smaller issues (stale strings, font sizing, locale fallbacks) but no P0s. v0.25.9+ polish.
- **OpenLoopCard bring-into-view render glitch** (vitals B2) — the OpenLoop's `bringIntoViewOnFocus` modifier may collapse the field to zero height on the first composition. Hard to reproduce; deferred until a real-device repro.
- **LetterInbox non-lazy layout** (notes #11) — the inbox is a `Column` + `verticalScroll`, not `LazyColumn`. Won't scale to 30+ letters. v0.25.9+ follow-up.
- **`friendlyLetterDate` always uses `Locale.ENGLISH`** (notes #13) — weekday names in English even on a Tamil/Hindi locale. v0.25.9+ follow-up.
- **Watch-connect real fix (v0.25.3-WP-B-real)** — still needs the user's `adb logcat -s MindAnchor/HealthConnect:V` capture.
- **Manual smoke** — AVD unstable on this Windows host; real-device install verified on the Motorola signature at 172.16.68.207:38535.
