# v0.33.0 — Needs-First Redesign + Visible Data Sources

**Date:** 2026-08-17
**Status:** Approved (user directive 2026-08-17)
**Author:** Mavis (acting as senior UI designer)
**Scope:** Single release. Home + Settings + the integration surface for Health Connect, COROS, and camera PPG.

## Goal

Make MindAnchor honour one core design move that it has not yet made: **ask
the user what they need first, before showing them anything else.** The home
must be a "now" surface that does three things in order:

1. Says good morning/evening, then asks one question.
2. Surfaces where the data comes from, in case the user wonders.
3. Gets out of the way.

This is the second major visual/structural change after v0.32.0's home
declutter. Where v0.32.0 *removed* the OpenLoop card, v0.33.0 *replaces*
the Distress Thermometer card with a needs-first card and *adds* a
"Where it comes from" data sources card that makes the Health Connect +
COROS + PPG integration visible for the first time.

The redesign is grounded in:

- Linehan 1993, DBT Distress Tolerance (ch. 8): validate, then offer
- Iglewicz & Hoaglin 1993: robust z-scores for N-of-1
- Gál et al. 2020, J Affect Disord (mindfulness meta-analysis)
- mindLAMP / Jacobson 2019, J Nerv Ment Dis 207:893-6
- Stanley & Brown 2012, Safety Planning Intervention
- v0.28.0 BPD-strict design spec
- Existing in-repo research notes (`docs/research/14-v0.26.6-audit.md`,
  `docs/research/08-sensing-architecture.md`,
  `docs/research/20-coros-sidechannel.md`)

The user-directed research that informed this is captured in
`docs/design/v0.33.0-research.md` (the explore-agent output, to be
committed alongside this spec).

## Why now

Two pain points were named explicitly by the user in 2026-08-17:

1. "Declutter the app as far as possible" — the home still has five
   visible sections (clock, greeting, distress, notes, "Right now"
   with three buttons). The Distress card is one question followed by
   one button, the Notes card is an input box followed by a Save
   button, the "Right now" section is three separate buttons. Five
   question+button pairs in one screen is not a calm home.

2. "There's Coros in my phone, Health Connect, and MindAnchor — drive
   all 3, integrate, get insights." The data integration is *fully
   built* (Health Connect reads, COROS side-channel reads, PPG
   reads, merge in `CorosVitalSource.mergeWith`, wellness card surfaces
   the merged view) but it is *invisible*. The user has to navigate
   Settings → Measuring to see that COROS is even there. The home
   never tells them where today's "above your usual" reading came
   from. That is a real product gap, not a decoration question.

## What ships in v0.33.0

### A. The new home

The home becomes four sections, not five:

```
┌─────────────────────────────┐
│  1:53  Here, now.            │  (clock + greeting, time-aware)
│                              │
│  What do you need right now? │  (new — needs-first card)
│  • Be heard                  │
│  • A moment                  │
│  • Check in                  │
│  • Get through this          │
│                              │
│  Where it comes from         │  (new — data sources card)
│  Wearable   last sync 2h ago │
│  Coros Pace 3                │
│  PPG        yesterday 7:42am │
│                              │
│  Notes                       │  (compact, same as today)
│  [Jot something down...]    │
│  Save                        │
│  Phone end-to-end note · …   │
│  View all                    │
└─────────────────────────────┘
```

In words:

- Clock + greeting: unchanged.
- **"What do you need right now?"** — replaces the "How is it right
  now? / Ground me here" card. Same validation-first principle, but
  presented as four clearly labelled one-tap affordances, each one
  sentence and one destination deep.
- **"Where it comes from"** — replaces nothing. Adds a new card
  showing the three data sources (Health Connect / Coros / PPG) and
  the most recent signal from each. The user can see at a glance
  whether the wrist and the watch are talking to the app, and how
  fresh the data is.
- Notes card: same as v0.32.1. Compact. Stays.
- "Right now" three-button section: **removed**. The three actions
  (chain capture, IFS picker, export) are still reachable from the
  "Get through this" option in the needs-first card and from the
  top-right of the support screen, but they no longer get a
  permanent home.

### B. The four needs-first affordances

Each is one sentence and one tap. None of them is a settings link.

1. **"Be heard"** → opens the NoteActivity, but the launcher's
   existing quick-notes input also stays on the home. The
   affordance is for a person who wants the full notes screen —
   free text, no auto-classify, longer form.
2. **"A moment"** → opens the Distress Thermometer. The current
   Distress card moves from the home to the new entry point, with
   one small copy change: the home card previously said "Ground me
   here" which is action-language; the new "A moment" is
   need-language. The Distress screen itself does not change.
3. **"Check in"** → opens a new compact check-in surface: the
   wellness card's full view (today's five signals against the
   rolling baseline). This is the v0.20.5 wellness card promoted
   to an explicit destination. If the user has not connected
   Health Connect, the surface shows the same "connect your watch
   to start" placeholder.
4. **"Get through this"** → opens a small sub-menu with the three
   reflective actions: chain capture, IFS picker, export. This is
   where the "Right now" buttons move to. The three keep their
   one-tap nature, but they are now behind a "Get through this"
   door so the home scroll is not dominated by them.

This is the "needs-first" pattern: validate the need, then offer
one well-shaped path. It is the design move that BPD-safe
launchers are missing today, per the design research.

### C. The "Where it comes from" data sources card

A new card. One row per source. BPD-safe copy: the labels are the
source names, the body is "what was last seen" — no scores, no
recommendations, no "your data is great/worrying" labels.

Each row shows:

- The source name: **Wearable**, **Coros Pace 3**, **PPG**
- A status line: "last sync 2h ago", "last reading yesterday at
  7:42 am", "no readings yet", or "not connected"
- A tap target that opens the right surface:
  - Wearable → Settings → Measuring → Health Connect
  - Coros → Settings → Measuring → COROS form
  - PPG → PpgScreen (existing)

The card is built from three new state flows in
`LauncherViewModel`:

- `healthConnectStatus: StateFlow<HealthConnectStatus>` — derived
  from `HealthConnectSource.isAvailable` +
  `HealthConnectSource.hasAnyPermissions`.
- `corosDataStatus: StateFlow<CorosDataStatus>` — derived from
  `CorosVitalSource.lastSyncEpochMs` + `CorosAuth.connectionState`.
- `ppgLastMeasurement: StateFlow<LocalDateTime?>` — derived from
  the new `PpgSessionStore.lastSession()`.

Each state flow has a tiny mapping to a status line in the card.
The card itself is one new composable, `DataSourcesCard`, in
`launcher/DataSourcesCard.kt`.

### D. Settings → Sources

The existing `SettingsGroup.MEASURING` group gets two structural
changes:

- It is renamed to `SettingsGroup.SOURCES` in the public enum
  (and the corresponding `R.string.settings_group_measuring` is
  renamed `R.string.settings_group_sources`). This is a strings.xml
  edit and a one-line enum rename — no behaviour change.
- The COROS bridge form, the Health Connect section, and the PPG
  section are visually grouped under a single "Sources" header,
  with a one-line subtitle that names the three sources. The
  existing sections do not change.

This makes the "what watches the app is talking to" answer visible
in one place, in both Home and Settings, instead of being scattered
across three subgroups.

### E. Copy changes (clinical-review surface)

A small set of string changes, all BPD-safe and consistent with the
existing "validate then suggest" voice:

- `home_distress_card_title` ("How is it right now?") is replaced by
  `home_needs_title` ("What do you need right now?").
- `home_distress_card_caption` is replaced by
  `home_needs_caption` ("Four doors. Pick the one that's closest to
  what you need. There is no wrong door.").
- New strings for the four affordances:
  - `home_needs_be_heard` = "Be heard"
  - `home_needs_moment` = "A moment"
  - `home_needs_check_in` = "Check in"
  - `home_needs_get_through` = "Get through this"
- New strings for the data sources card:
  - `home_sources_title` = "Where it comes from"
  - `home_sources_caption` = "Three readings. One is the watch on
    your wrist, one is the watch you wear, one is the finger you
    put on the camera. None of them is right or wrong."
  - `home_sources_wearable` = "Wearable"
  - `home_sources_coros` = "Coros Pace 3"
  - `home_sources_ppg` = "PPG"
  - `home_sources_status_*` (one per source, with a "last sync 2h
    ago" / "no readings yet" / "not connected" shape)
- New string for the "Get through this" sub-menu:
  - `home_get_through_title` = "Pick what fits this moment"
- `right_now_section` / `right_now_caption` / `right_now_chain` /
  `right_now_ifs` / `right_now_export` are removed from the home
  surface (the strings stay in resources, marked as reserved, in
  case they return).

All clinical-review surface. The new strings will be re-reviewed
under `docs/CLINICAL_REVIEW.md` before the release goes out.

## What does NOT ship in v0.33.0

- The `v0.32.1` Letters/Generate-now flow. Unchanged.
- The LLM end-to-end verify on phone. Unchanged — that is the
  v0.32.1+ outstanding task.
- The "Data Sources" surface is read-only. No "Connect Coros from
  home" button. The user still has to go to Settings for the
  Coros form. The card's "not connected" status makes that
  obvious.
- No changes to Settings beyond the rename and the section
  grouping.
- No new distress tools. The Distress Thermometer screen is
  unchanged.
- No changes to Support, Letters, Notes, Chain capture, IFS
  picker, Export.

## Acceptance criteria

1. Home shows exactly four sections in this order: clock/greeting,
   "What do you need right now?", "Where it comes from", Notes.
2. "What do you need right now?" has four labelled affordances.
   Tapping each one opens the right destination.
3. "Where it comes from" shows three rows, one per source. Each
   row's status line updates when the underlying state changes
   (e.g. after a Health Connect permission grant).
4. Tapping a data sources row opens the right surface (Settings →
   Measuring for HC and Coros, PpgScreen for PPG).
5. Settings → Measuring is renamed to Settings → Sources. The
   string id changes; the behavioural code is unchanged.
6. All strings referenced in the home surface resolve (no
   `MissingResource` warnings). The clinician-pack.md regen
   produces a clean diff.
7. All existing FindingTests pass.
8. v0.33.0 APK installs on the user's phone (ZD2232FCR5) and
   the four home sections render as designed in the screenshot
   test.
9. No regression in the v0.32.1 Letters generate-now flow
   (untouched in v0.33.0).
