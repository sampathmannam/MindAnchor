# v0.25.2 — letter inbox + reader (closes the v0.24.0 letter UI gap)

**Date**: 2026-08-11
**Status**: drafted
**Part of**: v0.25.2 (also includes v0.25.2-B letter reader-mode, drafted separately)
**Closes**: the v0.24.0 letter UI gap. The v0.24.0 spec ("a new entry on the home screen, on the Reading card group … a new 'Letters' inbox") was partially implemented: `LetterWriter` / `LetterStore` / `LetterScheduler` shipped, the inbox UI did not. This spec finishes the inbox + reader surface; the v0.24.0 letter feature is then end-to-end.

## Decisions in scope

- A new `LauncherSurface.Letter` (sibling of `Home, Drawer, Settings, Ppg, Report`).
- A new `LetterScreen` Composable with internal state for inbox ↔ reader.
- A new "letters" TopEnd corner shortcut (third under support, above notes + history). 7 corners total.
- The notification's `contentIntent` opens the letter reader for that day's letter, not the launcher home.
- A × + confirm delete pattern on each letter row (matches the existing Notes list).
- A toggle + time + "Generate now" row in Settings → Reading, mirroring the existing "Last night's look" row.

## Out of scope (deferred to v0.25.2-B)

- Reader-mode text sizing (WCAG 2.2 SC 1.4.4). The reader in this spec renders at the default `bodyLarge`. Spec 2 adds the size toggle.
- Snooze ("Pause for 7 days" / "Pause for 30 days"). Nice-to-have, can ship in v0.25.3.
- WebDAV backup of letters. The v0.24.0 spec said letters would be included in the sealed backup; the existing `SealedCodecs` doesn't carry letters yet, and adding that is its own spec.
- "Letters" entry in Settings → Reading. The corner shortcut is the entry; the toggle + time live in the Reading section (one tap from Settings).

## Why this scope

The v0.24.0 spec said: "A new 'Letters' inbox — list of letters, latest first; each row: date + first sentence of the letter; tap to read full letter; delete letter; Generate now button." None of that UI shipped. The senior-tester audit for v0.25.1 listed the letter as "Weekly letter (v0.25.0) | `letters/LetterWriter.kt` | Last built: 2026-08-10 — weekly cadence" but did not exercise the inbox (marked "NOT TESTED" in iter 3). The user picked "letter reader-mode" for v0.25.2 not knowing the reader surface was missing; the honest fix is to build it.

## Architecture

### 1. New surface + state in the launcher

**`LauncherSurface` enum** (`launcher/HomeScreen.kt:85`):
```kotlin
private enum class LauncherSurface { Home, Drawer, Settings, Ppg, Report, Letter }
```

**State in `HomeScreen`** (sibling of `surface`, `reportCameFrom`):
```kotlin
var letterSelectedDate by remember { mutableStateOf<java.time.LocalDate?>(null) }
var letterCameFrom by remember { mutableStateOf(LauncherSurface.Home) }
```

`letterSelectedDate = null` means inbox view; non-null means reader for that date. `letterCameFrom` mirrors `reportCameFrom` so the reader's back button returns to wherever the user came from (Home vs Settings).

### 3. Notification routes to the reader, not the home

**`LetterScheduler.kt:169-174` currently:**
```kotlin
val openIntent = PendingIntent.getActivity(
    context, 0,
    context.packageManager.getLaunchIntentForPackage(context.packageName),
    PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE,
)
```

**New behaviour**: build the intent with a `letter_date` extra and target `HomeActivity` directly:
```kotlin
val openIntent = PendingIntent.getActivity(
    context, notificationId,
    Intent(context, org.mindanchor.HomeActivity::class.java)
        .setAction("org.mindanchor.letters.OPEN_LETTER")
        .putExtra("letter_date", letter.date.toString()),  // ISO local date
    PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE,
)
```

**`HomeActivity.onCreate`** reads the extra:
```kotlin
val openDate = intent?.action == "org.mindanchor.letters.OPEN_LETTER"
    .let { intent?.getStringExtra("letter_date")?.let(java.time.LocalDate::parse) }
val letterSurface = if (openDate != null) {
    letterSelectedDate = openDate
    letterCameFrom = LauncherSurface.Home
    LauncherSurface.Letter
} else null
```

(The exact plumbing is in `HomeScreen`'s state read from `LocalSavedStateRegistryOwner` or a side-effect; the spec leaves the exact home-state wiring to the implementation but the intent shape is fixed.)

### 4. New `LetterScreen` Composable

**`app/src/main/java/org/mindanchor/letters/LetterScreen.kt`** (new file):

```kotlin
@Composable
fun LetterScreen(
    /** All letters, oldest first (matches LetterStore.letters). */
    letters: List<Letter>,
    /** null = inbox; non-null = reader for that date. */
    selectedDate: LocalDate?,
    /** True iff Phi-4 is installed and runnable. */
    modelFits: Boolean,
    onSelect: (LocalDate) -> Unit,
    onBack: () -> Unit,
    onDelete: (LocalDate) -> Unit,
)
```

It dispatches:
```kotlin
if (selectedDate != null) LetterReader(
    letter = letters.firstOrNull { it.date == selectedDate },
    onBack = onBack,
    onDelete = { onDelete(selectedDate) },
) else LetterInbox(
    letters = letters,
    modelFits = modelFits,
    onSelect = onSelect,
    onDelete = onDelete,
    onBack = onBack,
)
```

**`LetterInbox`** (new, private to the file):
- `Column` with `safeDrawingPadding`, `verticalScroll(rememberScrollState())`, `padding(Spacing.Edge)`.
- Top: `TextButton(onClick = onBack) { Text(stringResource(R.string.action_back)) }`.
- Header: "A letter from your week" (`R.string.letters_inbox_title`).
- Explainers (1 short paragraph): "Written on this phone each morning by the same model that writes the nightly report. Tap any letter to read it."
- "Generate now" `TextButton` at the bottom of the list — gated on `modelFits` and on `LetterScheduler.canRunNow()`. Disabled with "Phi-4 isn't installed" when `!modelFits`.
- Empty state:
  - If `!modelFits`: "No letters yet. Phi-4 isn't installed — open Settings → Model to install it." (`R.string.letters_empty_no_model`)
  - Else: "No letters yet. The first arrives at 8 AM, once enough days have passed." (`R.string.letters_empty`)
- Letter list: one `LetterRow` per letter, newest first. Group separator: "Today" / "Yesterday" / weekday name (e.g. "Monday") / "Earlier" — same friendly-day shape as the report (`report.friendlyDay` is private; we extract `internal fun friendlyLetterDate(date: LocalDate, today: LocalDate): String` and the test pins both bounds). The threshold for "Earlier" is **> 7 days ago**; 1–7 days ago shows the weekday name.

**`LetterRow`** (private to the file):
- A `Row` at `Modifier.heightIn(min = 48.dp).clickable { onSelect(letter.date) }` containing:
  - A `Column(weight = 1f)` with two `Text`s:
    - Date: same friendly-day string as the group separator, or `date.format(MMM_d)` if the date is more than 7 days old. Style `titleSmall`.
    - First-line preview: `letter.body.lineSequence().firstOrNull().orEmpty().take(60).let { if (it.length == 60) "$it…" else it }`. Style `bodyMedium`, color `onSurfaceVariant`.
  - An `IconButton(onClick = onDelete) { Icon(Icons.Default.Close, contentDescription = "Delete letter") }` — visible × button (matches the Notes list).

**`LetterReader`** (new, private to the file):
- `Column` with `safeDrawingPadding`, `verticalScroll(rememberScrollState())`, `padding(Spacing.Edge)`.
- Top row: `TextButton(onClick = onBack)` on the left, `IconButton(onClick = { pendingDelete = true })` on the right (delete from the reader too, for symmetry).
- Title: the friendly date, style `headlineMedium`.
- Body: `Text(letter.body, style = MaterialTheme.typography.bodyLarge)` with `Modifier.padding(vertical = Spacing.Loose)`.
- Disclaimer footer (the same shape as the report): "A letter is what your own data looked like to a model on this phone. It is not advice." (`R.string.letters_disclaimer`)
- Delete confirm: `if (pendingDelete) AlertDialog(...)` with the same `pendingDeleteId` pattern as `NoteScreen.kt:542-560`.

### 5. Settings → Reading: letter toggle + time + generate

In the `if (group == SettingsGroup.READING)` block of `SettingsScreen.kt` (around line 1500), add a new sub-section above the "Last night's look" row:

```kotlin
SectionHeading(R.string.letters_section, SettingsSection.PULSE, goals)
Text(
    text = stringResource(R.string.letters_explainer),
    style = MaterialTheme.typography.bodySmall,
    color = MaterialTheme.colorScheme.onSurfaceVariant,
)
val modelFits by viewModel.modelFits.collectAsState()  // existing ModelStore.fit() exposed as a flow
val lettersEnabled by viewModel.lettersEnabled.collectAsState()
// The toggle is always editable — the user can opt in before installing Phi-4.
// "Generate now" is what depends on modelFits; opting in just arms the alarm.
Row(
    modifier = Modifier.fillMaxWidth().heightIn(min = 48.dp)
        .toggleable(value = lettersEnabled, role = Role.Switch) { viewModel.setLettersEnabled(it) }
        .padding(top = 8.dp),
    verticalAlignment = Alignment.CenterVertically,
) {
    Text(stringResource(R.string.letters_toggle), style = MaterialTheme.typography.bodyLarge, modifier = Modifier.weight(1f))
    Switch(checked = lettersEnabled, onCheckedChange = null)
}
val lettersTime by viewModel.lettersTime.collectAsState()
TextButton(enabled = lettersEnabled, onClick = { showLetterTimePicker = true }) {
    Text(stringResource(R.string.letters_time, "%02d:%02d".format(lettersTime.first, lettersTime.second)))
}
val lettersRunning by viewModel.letterRunning.collectAsState()
TextButton(
    enabled = !lettersRunning && lettersEnabled && modelFits,
    onClick = viewModel::runLetterNow,
) {
    Text(stringResource(if (lettersRunning) R.string.letters_running_now else R.string.letters_run_now))
}
val unreadCount by viewModel.unreadLetterCount.collectAsState()
TextButton(
    enabled = unreadCount > 0,
    onClick = onOpenLetters,  // the new "letters" entry — opens the inbox
) {
    Text(stringResource(R.string.letters_open_inbox, unreadCount))
}
```

The existing `SettingsViewModel` already exposes `lettersEnabled` / `lettersTime` flows on the store side. We add the new fields:

- `letterRunning: StateFlow<Boolean>` — true while a "Generate now" is in flight.
- `unreadLetterCount: StateFlow<Int>` — **for v0.25.2 this is "letters whose date is after the user's install date", a stand-in for a per-letter read flag**. A real `readByUser: Boolean` per `Letter` and a derivation that drops read letters is a v0.25.3 add. The "Open inbox (N)" button in Reading shows the count; tap goes to the inbox (which shows all letters, not just unread — the badge is a count, not a filter).
- `setLettersEnabled(b: Boolean)` (already on the store).
- `runLetterNow()` — calls the existing `LetterWriter` directly with the same guard as `LetterScheduler.fireNow()`.

**`modelFits` is the same `ModelStore.fit()` check** the rest of the app uses (`SettingsViewModel` already exposes it; we add a public read for this view).

### 6. Notification extras round-trip

- The notification's `contentIntent` is built in `LetterScheduler.notify(...)` (line 169).
- `HomeActivity.onCreate` (and `onNewIntent`) reads `intent.getStringExtra("letter_date")` and pre-populates the state.
- The state's initial composition checks this on first render and switches to `Letter` if the extra is present.

(If `HomeActivity` already overrides `onNewIntent` for the launcher intents, this fits in the same place.)

### 7. Data flow summary

```
LetterWriter  ──▶ LetterStore.save(letter)
                            │
                            ▼
                       LetterStore.letters  (Flow<List<Letter>>, oldest first)
                            │
                            ▼
        HomeActivity.onCreate / onNewIntent
                            │
       ┌────────────────────┼──────────────────────┐
       ▼                    ▼                      ▼
   letterSelectedDate   letterSelectedDate     letterSelectedDate
     = null              = specific date       = null
       │                    │                      │
   LetterInbox        LetterReader            LetterInbox
       │                    │                      │

```

### 8. Edge cases

- **No Phi-4 model**: `modelFits = false`. The "letters" corner shortcut is still shown (always-visible entry, matches the "Read it" pattern), but tapping the inbox shows the empty state with the install prompt. The "Generate now" button is disabled with the same message.
- **No letters yet (model installed)**: same `letterEmpty` empty state. The toggle is still editable; the user can opt in before the model is ready and the first letter will appear after the alarm.
- **Notification fired but the letter is gone (user deleted from another path)**: `LetterReader` is null-tolerant (`letters.firstOrNull { it.date == selectedDate } == null`); the reader renders a soft empty state: "This letter is no longer on the phone." and an OK button to go back to the inbox. Same pattern as the report's "Nothing yet" state.
- **Back from reader → inbox**: pressing back when `selectedDate != null` clears `selectedDate` to null but keeps `surface = Letter`. The next back press goes to wherever `letterCameFrom` says (Home or Settings). This is the same nesting as `reportCameFrom`.
- **Two letters with the same date**: the ledger dedupes by date (`save` already filters existing), so this can't happen. Finding test pins the dedup.
- **A letter fails the `NarrationGuard`**: it never lands in the store; the user never sees it. `LetterWriter` already calls the guard, so this is unchanged.

## Finding tests (the regression net)

Each fix / surface gets a finding test (~5 each) so a regression on any of the v0.24.0 letter-UI promises fails CI:

1. `LetterSurfaceWiringFindingTest` (5 tests) — `LauncherSurface` includes `Letter`; `letterSelectedDate` default is null; `letterCameFrom` defaults to `Home`; `onOpenLetters` is a non-null `() -> Unit` param; `LetterScreen` is reachable from `LauncherSurface.Letter`.
2. `LetterInboxLayoutFindingTest` (5 tests) — "Generate now" disabled when `!modelFits`; empty-state branches resolve to the correct string; inbox list is newest-first; "letters" label exists in `strings.xml`; the corner shortcut click handler is wired in the TopEnd Column.
3. `LetterReaderLayoutFindingTest` (5 tests) — title is the friendly date; body is the full letter text (no truncation in the reader); back button is a `TextButton` (not a system back); delete from the reader routes to the same `pendingDelete` confirm; the missing-letter fallback renders the soft empty state.
4. `LetterDeleteConfirmFindingTest` (5 tests) — row × button uses `IconButton` (not gesture); tap on × sets `pendingDeleteDate`; `AlertDialog` dismisses cleanly on cancel; `onDelete(date)` is called once on confirm; the dialog's confirm string exists in `strings.xml`.
5. `LetterDateFormatFindingTest` (5 tests) — `friendlyLetterDate` for today = "Today"; for yesterday = "Yesterday"; for 3 days ago = weekday name; for 14 days ago = `MMM d`; for 14 days ago last year = `MMM d, yyyy`.
6. `LetterNotificationIntentFindingTest` (5 tests) — `LetterScheduler.notify(...)` builds the intent with the `letter_date` extra; the action is `OPEN_LETTER`; the target component is `HomeActivity`; the date format is ISO local date; the PendingIntent flags include `FLAG_IMMUTABLE`.
7. `SettingsLetterControlsFindingTest` (5 tests) — toggle uses `Switch` + `toggleable`; time `TextButton` is enabled only when `lettersEnabled`; "Generate now" is disabled when `!modelFits`; "Open inbox" is enabled only when `unreadCount > 0`; the section heading uses the new `letters_section` string.
8. `LetterUnavailableReaderFindingTest` (5 tests) — when `selectedDate` has no matching letter, the reader renders the soft empty state; the OK button calls `onBack`; the back chain still works (no infinite loop); the surface is not silently closed; the user can navigate back to the inbox.

## Acceptance

- The "letters" TopEnd corner shortcut is the visible entry on the home; tapping it opens the letter inbox.
- The daily-letter notification, when tapped, opens the letter reader for that day's letter. Pressing back returns to wherever the user came from (Home by default, Settings if they came from there).
- A user with Phi-4 installed sees one letter per day in the inbox, latest first, with a friendly date and a one-line preview.
- A user without Phi-4 sees the corner shortcut and the inbox screen, with an empty state that names the install path (Settings → Model).
- × on a row → confirm dialog → confirm → letter is removed from the store and the inbox updates.
- Settings → Reading has a new "Daily letter" sub-section with a toggle, a time picker, a "Generate now" button, and an "Open inbox (N)" button. Disabled states are explicit and have the same look-and-feel as the existing "Last night's look" controls.
- The senior-tester audit (v0.25.1) listed "letter UI" as untested; the v0.25.2 audit (post-implementation) walks the new surface and finds no P0/P1 bugs.
- No new outbound network calls; no new permissions; the letter inbox reuses the existing `letters` DataStore. The `NetworkCallsForbiddenTest` still passes.

## Acceptance string

- A new user installs v0.25.2, opts into the daily letter in Settings → Reading, installs Phi-4, and at 8:00 the next morning gets a notification "A letter from your week" with the first 1–2 lines of the letter. They tap the notification, read the full letter, press back, and land on the home. They open the home and tap the new "letters" corner shortcut; the inbox shows today's letter, they tap it, read it again, press back, and land on the inbox. They press back again and land on the home.

## Out of scope (deferred to v0.25.2-B and beyond)

## Why this spec is two, not one

The user picked "letter reader-mode (WCAG 2.2 SC 1.4.4)" for v0.25.2 not knowing the letter reader didn't exist. The fix is the inbox + reader first (this spec) and reader-mode second (spec 2). Splits naturally: this spec lands the missing surface, spec 2 adds the size toggle on top. Both ship in v0.25.2; this spec is the one that closes the v0.24.0 gap, spec 2 is the WCAG win.
