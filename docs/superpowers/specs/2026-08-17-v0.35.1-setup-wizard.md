# v0.35.1 — Setup Wizard for 3-way Data-Source Integration

**Date**: 2026-08-17
**Status**: APPROVED · ready to build
**Author**: brainstorming session, user-approved design

## Problem

The launcher v0.35.0 ships with three independent data sources — Health Connect,
the universal SmartwatchConnector (BLE GATT 0x180D), and the local PPG
camera — and a fourth (Coros via the OAuth2 web bridge) and a fifth (Polar
via OAuth2). They are all real and all wired. They are also all silent:
a user who has never opened Settings → Sources has no way to discover that
MindAnchor can read Health Connect at all, or that any of this exists.

The Settings → Sources screen is the right answer once a user is already
in Settings, but it asks for too much before that: BLE scan, OAuth2 forms,
camera permission, eight Health Connect permission toggles. A first-run
user wants one step at a time.

The user is the planner of the actual pilot, with a Coros Pace 3 on the
wrist, the Coros app on the phone, Health Connect installed, and
MindAnchor installed. The ask: a guided wizard that walks them through
the 3-source setup, source by source, with one decision per step.

## Design decision (already approved)

**Wizard not deep links.** The launcher could expose one-tap deep links
into each app's setup screen (Health Connect privacy screen, Coros
"connect a service" screen, etc.). It does not. The reasoning:

- The wizard makes MindAnchor's role in the integration visible. The
  user sees, step by step, that *MindAnchor* is what knits the three
  apps together. With deep links they would not.
- BPD-safe (Lindsay 2024 JMIR, IFS Schwartz 1995): the wizard validates
  the user is the one driving each step (tap → confirm → next). Deep
  links are invisible handoffs.
- The wizard can be re-run from Settings at any time. Deep links
  are one-shot.

**5 steps + done, not fewer.** The user wants a screen for each source,
not a single "Grant all permissions" screen, because a single
permissions screen is exactly the shape that gets dismissed. One
permission per step is the form a user reads.

## Shape

5 steps + a closing "Done" screen:

1. **Welcome** — "Set up your data sources." 1-line explainer for each
   of the 3 sources.
2. **Health Connect** — request the 8 HC permissions via the system
   permission contract (`HealthConnectClient.permissionController`).
3. **Pair a watch** — embed `SmartwatchesSection` (BLE scan,
   tap-to-connect, "Always reconnect" switch).
4. **Coros web bridge** — embed `PolarSection` (email + password form
   for the existing Coros OAuth2 path).
5. **PPG (optional)** — single CTA "Take a baseline reading" →
   `PpgScreen`.
6. **Done** — "You're set up." 3-row status summary, identical to
   `DataSourcesCard` on the home.

## Behaviour

- **Trigger**: on cold start of `HomeActivity`, after the goal-elicitation
  onboarding is done, if `!wizardCompleted && !userDismissedWizard`:
  launch `SetupWizardActivity` + `finish()` HomeActivity.
- **Back behaviour**: system back. Step 1's back finishes the wizard
  (sets `userDismissedWizard = true`); every other step's back goes to
  the previous step.
- **Skip**: every step except Welcome and Done has a "Skip" affordance.
  Per-step `skipped: Boolean` so the wizard re-opens at the right step,
  not from step 1.
- **YAGNI cuts** (BPD-strict):
  - No progress bar %.
  - No celebratory animation on Done.
  - No "back" affordance beyond system back.
  - No re-running the wizard from the wizard's own step list (user
    goes to Settings → "Run setup wizard again" instead).

## Data layer

`SetupPrefs` (DataStore named `setup_wizard`):

- `wizard_completed: Boolean = false`
- `welcome_seen: Boolean = false`
- `health_connect_skipped: Boolean = false`
- `pair_watch_skipped: Boolean = false`
- `coros_skipped: Boolean = false`
- `ppg_skipped: Boolean = false`
- `user_dismissed_wizard: Boolean = false`

The DataStore is per-app (no key rotation needed). It is wiped on app
data clear, which is fine — a wipe of app data is also a wipe of all
other prefs and is its own "I am starting over" gesture.

  step's Composable, its string keys, and its next-step callback)
- `app/src/test/java/org/mindanchor/onboarding/HomeActivityShowsWizardFirstTest.kt`
  — pins HomeActivity's wizard-launch behaviour

## Acceptance

- Cold start of a fresh install: goal-elicitation onboarding → home →
  wizard → home with 3 sources connected (HC, watch, Coros) + PPG
  baseline taken
- Cold start of an upgrade install: existing prefs, wizard not shown
- Re-run from Settings → "Run setup wizard again" → wizard at the
  first non-skipped step
- System back from step 1 → home, `userDismissedWizard = true`
- System back from step 2-5 → previous step, no data written
- "Skip" on a step → that step marked `skipped`, advance to next
- All 5 step Composables findable by finding-test string tokens
- 1479 + N unit tests pass (N ≥ 7)

## Out of scope (deferred to v0.36.0+)

- Garmin Connect (commercial-fee partner)
- Fitbit Web API (intraday HRV case-by-case approval)
- Withings Health Mate (geo-restricted)
- Polar OH1 PMD service (research-grade HRV, BLE proprietary)
- `mindanchor://polar-oauth-callback` intent filter (deferred — v0.35.0
  opens Polar auth in the system browser; user manually returns)
- Foreground service for continuous background streaming
- "Run setup wizard again" via long-press on the home's `DataSourcesCard`
  (deferred — the Settings entry is enough for v0.35.1)
