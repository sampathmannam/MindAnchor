# v0.35.0 — Wearables visible everywhere

2026-08-17 — design spec, building now

## Why

v0.34.0 shipped the universal SmartwatchConnector framework — any
Bluetooth heart-rate sensor, writing through Health Connect into the
existing wellness card. The data plane is done. The user has to see
the wearable story from three surfaces:

1. **Home screen** — replaces the "How is it right now?" distress
   thermometer with a "What do you need right now?" needs card
   (Lindsay 2024 JMIR; Schwartz 1995 IFS; Linehan 1993 DBT), and
   adds a "Where it comes from" data-sources card so the user can
   see which wearable just synced.
2. **Settings → Smartwatches** — a real section listing the
   registered connectors with availability, connect/disconnect,
   and "Scan for watches" so the BLE connector wired in v0.34.0 is
   actually discoverable.
3. **Polar AccessLink** — the second connector in the static
   roster. Polar's Nightly Recharge endpoint gives nightly HRV
   (RMSSD-derived) and Continuous HR (5-min RR samples) without a
   chest strap. Free self-serve OAuth2, no commercial fee (Garmin
   deferred because it requires a paid partner agreement).

## Architecture

Three independent layers, all built in this release. No new
permissions on top of v0.34.0 (Polar OAuth2 uses HTTPS via OkHttp).

### Layer 1: Settings UI (small)

`settings/SmartwatchesSection.kt` — one new Composable inserted in
the existing "Sources" group. Renders the connector roster from
`SmartwatchRegistry.state`, per-connector: vendor name, availability
("Ready" / "Tap to grant" / "No Bluetooth radio"), connect /
disconnect button, "Always reconnect" switch. Below the roster:
"Scan for watches" → calls `SmartwatchRegistry.discoverAll()` →
renders the device list with tap-to-connect rows. BLE_SCAN /
CONNECT permission gate: if not granted, the entire section
shows one "Tap to grant Bluetooth access" button that fires
`ActivityResultContracts.RequestMultiplePermissions`.

### Layer 2: Home redesign (medium)

Two new Composables in `launcher/`:

- **`NeedsCard.kt`** — replaces `HomeDistressCard`. Title "What
  do you need right now?", 4 affordances laid out in a 2×2 grid:
  - **Be heard** → opens SupportActivity (existing 8 surfaces)
  - **A moment** → opens ACCEPTS activity
  - **Check in** → opens DiaryCard activity
  - **Get through this** → opens `GetThroughSubMenu.kt` (a new
    half-screen sheet with 3 reflective actions: "What just
    happened?" / "Which part is loud?" / "Export for my
    therapist"; the first two open existing IFS / Unblending
    screens, the third runs the existing export flow)
- **`DataSourcesCard.kt`** — surfaces the connected wearables
  with last-sync timestamps. Reads from
  `SmartwatchRegistry.state.activeConnections` (BLE HR), the
  existing `coros_last_sync` (Coros), and a new
  `PpgSessionStore.lastSession()` (camera HRV). Three rows when
  any source is paired; one line "Nothing paired yet. Open
  Settings → Smartwatches to connect a watch." when nothing.

`HomeScreen.kt` changes: drop `HomeDistressCard` + `RightNowSection`,
add `NeedsCard` + `DataSourcesCard` in their place.

`LauncherViewModel.kt` exposes three new StateFlows
(`healthConnectStatus`, `corosDataStatus`, `ppgLastMeasurement`)
that the data-sources card reads. Implemented as a single
`combine(...)` of the underlying `CorosVitalSource.lastSyncEpochMs`,
a `HealthConnectClient` availability check, and the PPG store.

### Layer 3: Polar AccessLink OAuth2 connector (large)

Five new files in `vitals/polar/`:

- `PolarAuth.kt` — `Authorization Code` flow against
  `https://flow.polar.com/oauth2/authorization` and
  `https://polarremote.com/v2/oauth/token`. Self-serve client
  at admin.polaraccesslink.com. Polar tokens are long-lived
  (3-day TTL, no refresh needed) — store per user, not per
  session.
- `PolarApi.kt` — four endpoints, all `GET` against
  `https://www.polaraccesslink.com/v3`:
  - `/users/nightly-recharge/{date}` — HRV (RMSSD-derived) +
    overnight RHR
  - `/users/continuous-heart-rate/{date}` — 5-min RR samples
    (research-grade HRV if the user has a chest strap)
  - `/users/sleep/{date}` — sleep stages
  - `/users/activities/{date}` — steps + active minutes
- `PolarCredentialStore.kt` — EncryptedSharedPreferences
  (matches the Coros pattern, Keystore-backed).
- `PolarVitalSource.kt` — same shape as `CorosVitalSource`:
  cache to DataStore, `mergeWith` against Health Connect on
  read, `lastSyncEpochMs` flow.
- `PolarSyncWorker.kt` — WorkManager periodic worker, 6h
  interval + "Sync now" affordance from settings.

`SmartwatchRegistry.register(PolarAccessLinkConnector())` in
`MindAnchorApp.onCreate`. No new manifest permissions (HTTPS
via the existing `INTERNET` permission granted for the
GoingLightVpnService).

`Settings → Sources → Polar` row: email/password form (Polar's
`/oauth2/authorization` accepts Basic-style email + password on
the token exchange), then a status line ("Connected as
<email>" or "Disconnected") with a "Disconnect" button. The
"sync now" button forces a `PolarSyncWorker.doWork()`.

## Out of scope (v0.35.1+)

- Garmin Connect (commercial-fee partner agreement required)
- Fitbit Web API (intraday HRV case-by-case approval)
- Withings Health Mate (geo-restricted data availability)
- Polar OH1 PMD service (research-grade HRV, BLE proprietary)
- Foreground service for continuous background streaming
- v0.34.x follow-up: Settings → Sources rename applied
  (strings only, UI was missing)
